# Implementation Plan: Catalog search, install builder, trust profile, context cost, shader effects
Status: ready
Spec: specs/SPEC-2026-10-14-catalog-search.md (SPEC-2026-10-14-catalog-search), `Status: approved (Glib, 2026-10-14)`, commit 85581b1
Execution mode: multi-agent, chosen by the user

This repo is the plugin marketplace, not DevDigest. DevDigest skills, INSIGHTS.md and onion rules do not apply. The repo's own rules are CONTRIBUTING.md, `scripts/check-repo.mjs`, the ADRs in `docs/architecture-decisions/` and the spec. Never write a user-home or drive-letter absolute path in any file, including this plan, a test or a fixture. `check-repo.mjs` scans every text file outside `.git`, `node_modules` and `site`, and fails on those strings.

## Open questions & recommendations
All are non-blocking. Each carries an assumed default, and the main session confirms it or sends it back to spec-creator.
- ambiguity — AC-38 — default assumed: always-loaded tokens = Σ ceil((len(short name) + len(description)) / 4) per skill, agent and command. The spec says "names and descriptions", but its verify line says a 400-char description gives 100, which only holds if the name is excluded. Recommendation: spec-creator rewrites the verify as "name + description totalling 400 chars gives 100". The test fixture then uses name 4 + description 396. — blocking: no
- gap — AC-1/AC-2 — default assumed: one `hook` artifact per matcher group, named `<plugin>/<event>#<n>`. `n` is a 0-based running index per event across sources, in the order default `hooks/hooks.json`, then `plugin.json` inline, then custom path, then catalog entry. The description is built from event, matcher and command text. An MCP artifact's description is "<transport> MCP server" plus the command or URL. Recommendation: record this in the spec Contracts section. — blocking: no
- gap — AC-5 — default assumed: a skill needs `description`. An agent needs frontmatter with `description`; its `name` defaults to the file stem. A command's frontmatter is optional, and its description falls back to the first non-empty body line (max 200 chars). Frontmatter is read by an in-house top-level-key scanner (plain, quoted and `|` or `>` block scalars; all other keys are skipped). Recommendation: add the agent and command rules to AC-5. — blocking: no
- gap — AC-7 — default assumed: `.mcp.json` is read as `{ "mcpServers": {...} }`, and a flat server map is also accepted. A custom path may be a string or an array of strings, relative to the plugin root. A catalog entry may carry `hooks` and `mcpServers` fields. — blocking: no
- gap — AC-12 to AC-17 — default assumed: query tokens combine with AND; a token's dictionary translations combine with OR. No OR fallback on zero results. — blocking: no
- gap — edge case "Clipboard API unavailable" has no AC — default assumed: the text stays selectable and the message "Copy is unavailable here. Select the text and copy it manually." appears. It is pinned by e2e test `copy falls back when the clipboard API is missing`. Recommendation: add an AC. — blocking: no
- feasibility — AC-9 — default assumed: Node cannot be sandboxed off the network portably. The test preloads `test/helpers/no-network.mjs`, which makes `net`, `dns`, `fetch` and `http(s)` throw, and runs the build twice. The "network disabled" proof is therefore at process level. — blocking: no
- gap — AC-43 — default assumed: it is a main-session browser check on an index generated by `test/helpers/gen-index.mjs` at the 500 KB gzip budget. No automated proxy test is added.
- gap — design: the spec has no frames. The layout is assumed to be one page: a header with the search box, a results area, a builder panel and the plugin list. Trust and cost sit in a `<details>` on each plugin card. Recommendation: the main session confirms this. — blocking: no
- feasibility — `shaders` API is unknown to me. Lane 4 opens with a spike. If the spike finds a CDN fetch, `eval`, a Pro component or a licence that is not MIT, lane 4 stops and the main session decides. The spike also decides whether the CSP needs `blob:`, `worker-src` or `wasm-unsafe-eval`. — blocking: no
- assumed default — Node 22 or newer. `package.json` `engines` and `node --test` globs need it; CONTRIBUTING's "Node 20" line changes. npm (not pnpm) and `npm ci --ignore-scripts` in both workflows, with Chromium installed by an explicit `playwright install` step. esbuild needs no postinstall script, and lane 0 verifies this.
- assumed default — `check-repo.mjs` still accepts bare-string dependencies, while the build rejects them (AC-5). Because `check.sh` runs `check-repo.mjs` first, the only effect is a later failure. Left as is.
- assumed default — the test-only env `SITE_FAKE_FX=1` makes the bundler swap the WebGPU renderer for a fake one, so e2e can test lifecycle logic without a GPU. A test proves the default build never contains the fake.
- assumed default — assets get content-hashed names (`assets/app-<hash>.js`). The page reads `index.json?v=<sha256-8>`, so a stale cached index cannot mix with a new page. All URLs are relative, because Pages serves a project sub-path.
- note — the AC text below was copied from the spec as I read it. AC-58 and the closed Q-15 and Q-16 come from the approved version. If the main session finds drift, the spec wins.

## Acceptance criteria (from the spec, verbatim; Verify hints stay in the spec)
- AC-1 WHEN the build runs, the system shall emit one static index describing every plugin in the catalog and every skill, agent, command, hook and MCP server found inside those plugins, each with a type, name, owning plugin, description and, where applicable, body text. — proof: red-first integration
- AC-2 WHEN the build discovers artifacts, the system shall give each its namespaced name: skill `/<plugin>:<frontmatter name or folder name>`, command `/<plugin>:<file name>` (a subfolder adds a `:<folder>` segment), agent `<plugin>:<agent>`, MCP server `<plugin>/<server>`, hook `<plugin>/<event>#<index>`. — proof: red-first unit
- AC-3 WHERE the build is pointed at a fixture marketplace outside the published catalog, the system shall build from it exactly as from the real catalog, and shall never include fixture content in the deployed site. — proof: red-first integration
- AC-4 WHEN a push to main changes any indexed source (catalog, any `plugin.json`, skill, agent, command, hook config, MCP config, the UA→EN dictionary, the stop-word lists, the site sources or the lockfile), the system shall rebuild and redeploy the site. — proof: browser (main session), plus red-first integration asserting the trigger list covers each indexed source path
- AC-5 IF an artifact or curated file is malformed, THEN the build shall exit non-zero, name the file and the rule broken, and publish nothing. — proof: red-first unit
- AC-6 WHEN a skill frontmatter `name` differs from its folder name, the system shall use the frontmatter `name` for the namespaced name and show the folder path as the source location, and shall not fail. — proof: red-first unit
- AC-7 WHEN a plugin declares hooks or MCP servers inline in `plugin.json`, by a custom path in `plugin.json`, or in its catalog entry, the system shall read them together with the default `hooks/hooks.json` and `.mcp.json` and include all of them in the index and the trust profile, recording the source of each. — proof: red-first unit
- AC-8 WHEN the built site is used, it shall make no request to any origin other than its own: all scripts, styles, fonts, WebGPU code and data are served same-origin. — proof: e2e
- AC-9 WHILE the build runs in CI, it shall use no network access to produce the index and site, beyond installing locked dependencies in a prior step. — proof: red-first integration
- AC-10 The build output shall be deterministic: the same inputs produce byte-identical index files. — proof: red-first unit
- AC-11 The system shall search plugins, skills, agents, commands, hooks and MCP servers from one query box and render one result card per match. — proof: e2e
- AC-12 WHEN a query is entered, the system shall remove stop and filler words (Ukrainian and English lists kept in the repo) before matching. — proof: red-first unit
- AC-13 WHEN a query contains a type word (UA or EN: скіл/skill, агент/agent, команда/command, хук/hook, mcp, плагін/plugin, including inflected forms such as скіли, скіла, агенти), the system shall apply it as a type filter and not as a text term. — proof: red-first unit
- AC-14 WHEN a query token is a Ukrainian word in the curated UA→EN dictionary, the system shall match its English translations as well as the original token. — proof: red-first unit
- AC-15 The system shall treat the apostrophe variants `'`, `’` and `ʼ` as one character in queries and in the dictionary. — proof: red-first unit
- AC-16 WHEN a query has text terms, the system shall match them with fuzzy and prefix matching, ranking name and description matches above body matches. — proof: red-first unit
- AC-17 WHEN a query consists only of a type word, the system shall list all artifacts of that type, ordered by name. — proof: red-first unit
- AC-18 WHEN a query is empty or only stop words, the system shall show the full catalog (empty-query state) and not the no-results message. — proof: e2e
- AC-19 WHEN a query yields zero results, the system shall show a no-results message restating the interpreted query (type filter and text terms) with a control to clear the filter. — proof: e2e
- AC-20 The system shall render each result as a card showing type, name, owning plugin, description, highlighted matched fragments and a copy-install button. — proof: e2e
- AC-21 WHEN the copy button on any card is activated, the system shall copy the two lines `/plugin marketplace add HlibHav/dev-digest-ai-marketplace` and `/plugin install <owning plugin>@dev-digest-ai-marketplace`, because an artifact cannot be installed alone and the install fails without the marketplace, and shall announce "Copied" in a live region. — proof: e2e
- AC-22 WHEN the query or filters change, the system shall write them to the URL query string, and WHEN a page loads with such a URL it shall restore the same query and results. — proof: e2e
- AC-23 IF the URL query is longer than 200 characters, THEN the system shall truncate it to 200 and continue. — proof: red-first unit
- AC-24 The system shall treat all index text and the URL query as data: highlighting escapes content before adding markup, and query text is never turned into a regular expression unescaped, so no description, body, frontmatter value or query is interpreted as HTML or script. — proof: e2e
- AC-25 WHEN the page is loaded without JavaScript, the system shall show a readable list of every plugin with name, version, description, category, dependencies and install commands. Search, builder, trust and cost details and effects may require JS. — proof: e2e
- AC-26 WHERE JavaScript is available, the system shall enhance the static list with search, filters, builder and the trust and cost details without a visible layout jump. — proof: browser (main session)
- AC-27 WHEN a user selects plugins, the system shall add all their dependencies transitively, mark them "added automatically", and show each declared range. — proof: red-first unit
- AC-28 WHEN a plugin is present only as a dependency, the system shall not let the user deselect it while a selected plugin needs it, and shall say "required by X". — proof: e2e
- AC-29 The system shall output a valid JSON `.claude/settings.json` snippet with `extraKnownMarketplaces` for this marketplace (GitHub source `HlibHav/dev-digest-ai-marketplace`) and `enabledPlugins` listing every selected and every transitive plugin as `"<plugin>@dev-digest-ai-marketplace": true`. — proof: red-first unit
- AC-30 The system shall output `/plugin marketplace add HlibHav/dev-digest-ai-marketplace` followed by one `/plugin install <plugin>@dev-digest-ai-marketplace` per plugin in the set, and the snippet and the commands each have a copy button. — proof: e2e
- AC-31 The system shall state next to the ranges that they resolve against `<plugin>--v<semver>` release tags at install time and are not checked by the site. — proof: e2e
- AC-32 WHEN no plugin is selected, the system shall show guidance instead of the snippet and commands, with no copy buttons. — proof: e2e
- AC-33 The system shall compute at build time, for every plugin, a trust profile listing each hook with its event, matcher (or "no matcher") and source file; each MCP server with its transport (local command or URL) and source file; whether `scripts/` is present; and every network URL found in hook and MCP configuration. — proof: red-first unit
- AC-34 WHEN a hook event is `UserPromptSubmit`, `PreToolUse` or `PostToolUse`, the system shall flag it as broad, showing the matcher next to the flag when one exists. — proof: red-first unit
- AC-35 WHEN an MCP server uses an `http` or `sse` URL whose host is not loopback (`localhost`, `127.0.0.0/8`, `::1`), the system shall flag it as non-loopback; WHEN it uses a local command, it shall show command and arguments as text. — proof: red-first unit
- AC-36 The system shall show the trust profile on the plugin card with the wording "describes what this plugin declares, not a security audit", and show configuration URLs as plain text, never as links. — proof: e2e
- AC-37 WHERE a plugin has no hooks, MCP servers or `scripts/`, the system shall say "declares no hooks, MCP servers or scripts". — proof: red-first unit
- AC-38 The system shall compute for every plugin an estimated token count "always loaded" (names and descriptions of skills, agents and commands) and "loaded on invocation" (their bodies) as characters divided by 4, rounded up. — proof: red-first unit
- AC-39 The system shall label every cost figure as an estimate, state the method ("characters ÷ 4") and what is excluded (hook output, MCP tool descriptions and results). — proof: e2e
- AC-40 WHERE a plugin has no skills, agents or commands, the system shall show "0 tokens (no loaded content)". — proof: red-first unit
- AC-41 IF the built search index exceeds 500 KB gzipped, THEN the build shall fail naming the largest contributors. — proof: red-first unit (with a lowered budget on the fixture)
- AC-42 The build shall store at most 4 000 body characters per artifact in the search index; the full body still counts for cost. — proof: red-first unit
- AC-43 WHEN a query runs against a fixture index at the size budget, results shall appear within 100 ms after the debounce on a mid-range laptop, and loading the index shall not block the static list. — proof: browser (main session)
- AC-44 WHILE the index loads, the system shall show a loading state, and IF it fails to load, THEN it keeps the static list and shows an error with a retry control. — proof: e2e
- AC-45 The build shall finish in under 30 s for a fixture with 50 plugins of 5 artifacts each. — proof: red-first integration
- AC-46 The system shall be fully operable by keyboard (search, filters, cards, copy buttons, builder checkboxes) with a visible focus indicator and an accessible name on every control. — proof: e2e plus an automated accessibility check with zero serious violations
- AC-47 WHEN the result list changes, the system shall announce the result count in a polite live region. — proof: e2e
- AC-48 The system shall follow the user's light or dark preference with text contrast of at least 4.5:1 in both, and have no horizontal scroll at 320 px. — proof: e2e
- AC-49 WHERE the browser supports WebGPU and the user has not requested reduced motion, the system shall render an animated shader background behind the page header; otherwise it shall render a static CSS gradient in the same palette. — proof: e2e (both branches, WebGPU stubbed off) plus browser (main session) for the live effect
- AC-50 WHEN a result or plugin card receives pointer hover or keyboard focus, the system shall show a shader effect on that card whose colour is fixed per artifact type (one colour each for plugin, skill, agent, command, hook, MCP server), and WHEN hover and focus leave, the effect stops. — proof: e2e (effect state per card) plus browser (main session) for the visual
- AC-51 The system shall keep at most 2 live WebGPU canvases at any time (the header and at most one card); a card effect starting shall stop the previous card effect. — proof: e2e
- AC-52 WHILE the tab is hidden or an effect's canvas is out of the viewport, the system shall pause that effect's render loop. — proof: e2e
- AC-53 WHEN reduced motion is requested, the system shall show no animated effect anywhere (header static, card focus shown by a non-animated outline and colour). — proof: e2e
- AC-54 The effects shall load only after the static list and search are interactive, and IF WebGPU initialisation or the effects bundle fails, THEN the system shall fall back to the static look without an error message to the user and without affecting search or the builder. — proof: e2e
- AC-55 The JavaScript needed for search, builder and the static look shall be at most 60 KB gzipped; the effects code is loaded separately on demand and is excluded from this budget. — proof: red-first integration
- AC-56 Text and controls drawn over any effect shall keep contrast of at least 4.5:1 in every frame, so effects sit behind a scrim or use colours chosen for that. — proof: browser (main session)
- AC-57 The system shall use only components from the MIT-licensed `shaders` package, never paid "Pro" components, and the site shall credit the package. — proof: red-first integration plus e2e (credit visible)
- AC-58 Each type shall have a light and a dark colour (badge text, badge border, card glow, effect), and every badge-text colour shall have contrast of at least 4.5:1 against the page and card backgrounds in its theme. — proof: red-first unit (computes WCAG ratios for all 6 types × 2 themes × 2 backgrounds)

## Review focus
- Query of punctuation only (`"?!"`) → no tokens → empty-query state, not no-results → pinned by `engine.test.mjs` "punctuation-only query is the empty state" in step 13
- Unknown `?type=foo` or unknown names in `?plugins=` → ignored → `url-state.test.mjs` "drops unknown types and plugins" in step 16
- The same plugin ticked twice, or ticked and also a dependency → one entry → `builder.test.mjs` "idempotent selection" in step 15
- Clipboard API missing or rejecting → fallback message → `copy.spec.mjs` "copy falls back" in step 18

## Constraints
- The spec is the source of truth. Nobody edits it in this plan.
- Do not hand-edit `package-lock.json`; it comes from `npm install --save-exact --save-dev`. Source: the ADR's "frozen lockfile".
- The site makes no third-party request (AC-8). Source: ADR and spec NFR. Comply: all assets are bundled, and the CSP is `default-src 'none'`.
- Browser code never uses `innerHTML`, `insertAdjacentHTML` or `document.write`. It builds nodes with `textContent`. Source: AC-24. A test greps `site-src/` (step 16).
- `site-src/search` and `site-src/contract` are isomorphic and import no `node:*`. `scripts/` may import them. `site-src` never imports `scripts/` or `node:*`. A boundary test enforces this (step 25).
- No plugin or fixture file contains an absolute local path. Source: `check-repo.mjs:77`.
- Fixtures live under `test/fixtures/`, never `plugins/`. Source: AC-3 and `check-repo.mjs:69`. Malformed variants are generated in a temp dir at test time, not committed.
- The build is all-or-nothing: compute everything first, then write. Source: AC-5.
- No LLM or telemetry. No test library reaches the site bundle.
- `--ignore-scripts` on every `npm ci` in CI. Source: the spec's supply chain NFR.
- After `package.json` and the lockfile exist, any file that changes them is owned by lane 0 only.

## Risks
- The `shaders` API is unverified. Step 20 settles it, and its stop rule can block lane 4. If the CSP needs `unsafe-eval` or the package fetches remotely, the ADR needs a superseding record. Run the `researcher` agent if the spike cannot answer.
- Lanes 3A and 3B and 4 write to the same working tree but own disjoint paths. The e2e specs only run at level 3, so UI defects surface late; step 27 returns each failure to its lane.
- Headless Chromium has no real WebGPU. The e2e tests prove the lifecycle with the fake renderer, and only the main-session browser checks prove the real visuals.
- The core budget of 60 KB is unmeasured until step 25. If the inlined dictionary and stop-word text grow it, move them to a lazily fetched static file.
- A client-side MiniSearch build over a 500 KB (gzipped) index may be slow. AC-43 is checked by hand. The fallback is a prebuilt serialised index (`MiniSearch.loadJSON`), which is a later change.
- `npm ci --ignore-scripts` may break a dependency that needs an install script. Step 1 verifies it, and the plan's fallback is to run only that package's script explicitly.
- Fixtures and test files are scanned by `check-repo.mjs`. One stray user-home path fails the gate.
